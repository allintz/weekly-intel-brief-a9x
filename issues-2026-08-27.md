## Data source problems this run

**3. Metaculus community predictions are unavailable across every endpoint.** This is the most consequential gap. Tried, all authenticated with `$METACULUS_TOKEN` (which is valid, returns 200 with question metadata):
- `/api/posts/{id}/?with_cp=true` — returns the question but `aggregations.recency_weighted.latest` is `null` and `history` is empty
- `/api2/questions/{id}/` — same
- `/api/questions/{id}/` — same
- `/api/questions/{id}/aggregation_explorer/` — 404
- `/api/aggregation_explorer/?question_id=...` — 403
- scraping `metaculus.com/questions/5121/` — 403

Forecaster counts *do* come back (Q5121 is at 1,880 forecasters, 4,778 forecasts; the Democracy Threat Index questions return counts too), so the edition quotes counts and links only and states the gap as a methodology note. No Metaculus probability appears anywhere in this edition. The 2026-08-09 log shows the same symptom ("Metaculus API not returning predictions"), so this has been broken for at least three weeks and is not transient. Worth investigating whether the API now requires a different auth scope or whether aggregations moved to a new path.

**4. Polymarket returns stale prices on archived sub-markets, and it nearly produced a false headline.** The 2028 Republican nominee event contains a delisted Robert F. Kennedy Jr. sub-market that still returns `outcomePrices: ["0.49", ...]` while reporting `archived: true`, `active: false`, `volume: null`, `lastTradePrice: null`, `bestBid: null`, and \$15 of resting liquidity. Naively sorting the event's sub-markets by price makes RFK Jr. the GOP front-runner at 49%, ahead of Vance at 47.3%, and pushes the event's shown probabilities to a 130% sum.

The 2026-08-09 attempt-3 log did exactly this: it reported "RFK Jr. is now the 2028 GOP front-runner on Polymarket (49%, above Vance at 44%)" as a top signal. That edition never published, so it never reached the site, but the same bug would recur on any future run.
*Fix for the master prompt:* when rendering multi-candidate events, filter to `active == true and archived != true` before sorting, in addition to the existing `outcomePrices[0] > 0` rule. Documented as a reader-facing methodology note in this edition.

## Content corrections caught in the claim audit

Four claims were wrong before the audit and would have shipped:

- **Unemployment.** Draft said 4.2%, "unchanged from June", "labor market remains tight". Actual July BLS: 4.1%, payrolls **fell 23,000** against a +83,000 consensus, May and June revised down a combined 103,000, participation 61.4% (five-year low). The rate fell because people left the workforce. Corrected.
- **September primary calendar.** Draft listed only Rhode Island (Sep 9) and Delaware (Sep 15), from a bad search result. NCSL shows **four**: Massachusetts Sep 1, New Hampshire Sep 8, Rhode Island Sep 9, Delaware Sep 15. New Hampshire matters: its open Senate seat was the month's largest mover (+5pp to 87.5% D) and Polymarket carries only party-level sub-markets there, so the Sep 8 primary is what sets the nominee. Massachusetts is five days out. Added to Watching This Week, Key Dates, and the calendar.
- **Generic ballot attribution.** Mis-attributed to Silver Bulletin. Re-attributed to Abramowitz.
- **OpenAI post-mortem specifics.** 41 servers / root access / late-May awareness / June 27 alert all traced only to a search summary and could not be confirmed. Removed to `pending_review` and the bullet rewritten from Fortune-verified facts.
